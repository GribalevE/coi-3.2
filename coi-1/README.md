# COI LDT — выявление конфликта интересов при личном таможенном досмотре

Направление 01. Работает нативно на Windows без CGO, без MinGW, без WSL2.

## Требования

- **Go 1.26+** — https://go.dev/dl/ (версия задана в `go.mod`)
- **VS Code** — https://code.visualstudio.com/
- Расширение **Go** (`golang.golang`)

C-компиляторы не нужны: драйвер SQLite — `modernc.org/sqlite` (pure Go).

## Данные

Данные разделены на два независимых файла:

```
data/ern_full.sql   исходный дамп ЕРН (сервисом не читается)
data/dataset.json   лица — без деления на физических и должностных лиц
data/dltos.json     реестр должностных лиц таможенных органов
```

Конвертация выполняется один раз (или при обновлении дампа):

```
go run ./cmd/seed -in data/ern_full.sql -persons data/dataset.json -dltos data/dltos.json
```

или:

```
.\scripts\prepare-dataset.ps1
```

Далее реестр идентификации и мок СМЭВ читают эти же файлы: SQL-дамп в рантайме
не исполняется. Реестр должностных лиц можно править без пересборки датасета —
через раздел `/admin`.

Конвертер печатает состав обоих файлов и отдельно проверяет демонстрационную
пару `DL-014` / `P-185`. Если у пары нет записи ЗАГС, выводится предупреждение:
критерий K-01 (родство) не сработает, останутся K-02 (адрес) и K-10 (фамилия).

## Управление реестром должностных лиц

Раздел: `http://localhost:8080/admin/`

Учётные данные прототипа по умолчанию: **admin / 123**. Они задаются
переменными `COI_ADMIN_USER` и `COI_ADMIN_PASSWORD` и **должны быть изменены**
за пределами демонстрации.

Что можно делать: добавлять, изменять и удалять должностных лиц. Каждое
изменение сразу пишется в `data/dltos.json` и в журнал SQLite. Удаление
невозможно, если должностное лицо уже указано в поручениях, — журнал проверок
не должен терять ссылки.

## Параметры запуска

| Флаг | Переменная | По умолчанию | Назначение |
|---|---|---|---|
| `-addr` | `COI_ADDR` | `:8080` | адрес прослушивания |
| `-data` | `COI_DATA` | `data/dataset.json` | датасет лиц |
| `-dltos` | `COI_DLTOS` | `data/dltos.json` | реестр должностных лиц |
| `-db` | `COI_DB` | `var/coi.db` | файл журнала SQLite |
| `-token` | `AIS_TOKEN` | — (обязателен) | Bearer-токен интеграции с АИС |
| `-rules` | `COI_RULES` | `rules_v1.0.0` | версия набора правил |
| `-smev-latency` | `COI_SMEV_LATENCY` | `0` | задержка мока СМЭВ |
| `-admin-user` | `COI_ADMIN_USER` | `admin` | логин раздела управления |
| `-admin-pass` | `COI_ADMIN_PASSWORD` | `123` | пароль раздела управления |
| `-sql` | `COI_SQL` | — | устаревший режим: конвертация дампа на старте |

## Быстрый старт

1. Открыть папку проекта в VS Code: **File → Open Folder**.
2. Согласиться на установку расширения Go.
3. Подготовить датасеты: `.\scripts\prepare-dataset.ps1`
4. Собрать: `Ctrl+Shift+B` или `.\scripts\build.ps1`
5. Запустить: `.\scripts\run.ps1`
6. Проверка: `http://localhost:8080` — «Заполнить примером» → «Проверить поручение».
7. Реестр должностных лиц: `http://localhost:8080/admin/` (admin / 123).
8. Сценарий по API: `.\scripts\demo.ps1`

## Демо-сценарий

Пара `DL-014` / `P-185` — братья, адрес регистрации совпадает. Паспорт
проверяемого: `6697 478160`. Ожидаемый результат: установлено родство (запись
ЗАГС), совпадение адреса регистрации и фамилии; заключение — поручение подлежит
передаче другому должностному лицу.

## Ограничения прототипа

- Данные синтетические. Персональные данные реальных лиц не используются.
- Основной датасет не различает физических и должностных лиц: принадлежность
  к должностным лицам задаётся отдельным реестром.
- Источники: ЕРН, ЗАГС, разводы, эмансипация, налоговый учёт. Листы о
  дееспособности, родительских правах и занятости проверяются только при
  наличии записей; справочник «пост — район» не передан, поэтому K-13 не
  оценивается.
- Совпадение адреса регистрации не доказывает совместное проживание.
- Сервис формирует сигнал и обоснование. Решение по поручению принимает
  должностное лицо; журнал проверок append-only.
- Авторизация раздела `/admin` — учебная: статический логин и пароль, сессия в
  подписанной cookie, без CSRF-защиты и без блокировки перебора. Для стенда
  требуется переработка под корпоративный вход.
- Обмен с СМЭВ имитируется адаптером над датасетом; реальная интеграция требует
  замены адаптера и настройки транспорта.

## Что изменилось относительно Linux-версии

Драйвер SQLite: `mattn/go-sqlite3` → `modernc.org/sqlite` (pure-Go).
Нет CGO, нет gcc, нет MinGW. Остальная логика идентична.
