## 1. Порядок применения (важен)

`internal/admin/admin.go` использует поле `Person.Post`, поэтому правка
`internal/data/data_patch.md` делается **до** сборки, а не после.

1. Скопировать файлы из `patch2/` в корень `coi-1/`, удалить три каталога выше.
2. Применить `internal/data/data_patch.md` (3 фрагмента в `data.go`).
3. Применить `internal/api/api_patch.md` (3 фрагмента в `api.go`).
4. Собрать датасеты:
   ```powershell
   go run ./cmd/seed -in data/ern_full.sql -persons data/dataset.json -dltos data/dltos.json
   ```
5. Проверить сборку и тесты:
   ```powershell
   go build ./...
   go vet ./...
   go test ./... -race -count=1
   ```
6. Собрать и запустить:
   ```powershell
   .\scripts\build.ps1
   .\scripts\run.ps1
   ```
7. Открыть `http://localhost:8080` → «Заполнить примером» → «Проверить поручение».
8. Открыть `http://localhost:8080/admin/` → войти `admin` / `123` → добавить или
   изменить должностное лицо, вернуться на главную и повторить проверку.

## 2. Что именно решают задачи

**Задача 1 и 2. Отдельный датасет ДЛТО, без деления в основном датасете.**
`cmd/seed` раскладывает дамп на два файла. В `data/dataset.json` у всех лиц поле
`role` пустое — признака «физическое/должностное лицо» в основном датасете нет.
Принадлежность к должностным лицам задаёт `data/dltos.json`. При загрузке
`cmd/server` заводит всех лиц как `PHYS`, а затем перезаписывает записи из
реестра ДЛТО как `DLTO` — это нужно для внешних ключей поручений и для проверки
роли при создании проверки.

**Задача 3. Датасет отдельно + доступ через СМЭВ.**
Датасеты — файлы, сервис их не конвертирует на старте (`cmd/seed` делает это
один раз). Мок СМЭВ (`smev.NewFromBundle`) отдаёт сведения из этих же файлов и
сообщает состав источников (`Sources()`), из которого строится отчёт о покрытии.

**Задача 4. Правка реестра ДЛТО через HTML.**
`/admin/`: вход по логину и паролю (по умолчанию `admin` / `123`, переопределяются
`COI_ADMIN_USER` и `COI_ADMIN_PASSWORD`), сессия — подписанная HttpOnly-cookie на
30 минут. Формы: добавление, изменение, удаление. Любая правка пишется в
`data/dltos.json` и в журнал SQLite; при рассинхронизации выполняется откат.
Удаление блокируется, если должностное лицо уже указано в поручениях.

**Задача 5. Оформление и обоснование словами.**
Тёмно-синий верх с золотой линией, строгие карточки, шрифт Inter. Блок «уровень
риска» удалён: вместо него «Обоснование» — связный текст с сервера
(`internal/api/justify.go`), «Заключение», «Установленные обстоятельства» с
основанием по каждому пункту и «Полнота сведений» (что проверено, что нет).

**Задача 6. Полный датасет.** По умолчанию `-in data/ern_full.sql`; `run.ps1`,
`Dockerfile` и `docker-compose.yml` настроены на файлы, собранные из полного дампа.

**Задача 7. Запуск.** Команды — в §1. В моей среде Go отсутствует, поэтому
сборку и запуск я не выполнял: это надо сделать у вас.

## 3. Что проверено, а что нет

Проверено статически (скрипт `check_patch.py`):

- контракт id между `web/app.js` и `web/index.html`;
- все классы из разметки и из шаблонов админки описаны в `web/style.css`;
- баланс скобок в `web/app.js` и во всех Go-файлах поставки;
- отсутствие неиспользуемых импортов (эвристика по обращению к пакету);
- отсутствие дублирующихся имён функций внутри пакета `api`.

Не проверено: сборка, `go vet`, тесты, поведение в браузере, реальный вывод
`cmd/seed` на `data/ern_full.sql` (файла дампа в моей среде нет).

## 4. Риски и что смотреть в логе

1. **K-01 на полном датасете.** Конвертер достраивает ссылку `kinship → civil_registry`
   по паре лиц. Если пары DL-014/P-185 нет в записях ЗАГС, `cmd/seed` напечатает
   `WARNING: у демо-пары нет записи ЗАГС` — родство в демо не покажется.
2. **Гражданство.** Идентификация требует `RF` в гражданствах. Конвертер
   нормализует «Российская Федерация», «РФ», «Россия» → `RF` и предупреждает о
   лицах без гражданства.
3. **Должностные лица без паспорта** в дампе исключаются из реестра с
   предупреждением: без паспорта они не идентифицируются.
4. **Рассинхронизация реестра и журнала.** При удалении записи из `dltos.json`
   вручную (не через `/admin`) строка в журнале остаётся. Правьте реестр только
   через `/admin`.
5. **Docker.** `docker-compose.yml` монтирует `./data` внутрь образа, чтобы правки
   реестра не терялись. Перед `docker compose up` соберите датасеты локально,
   иначе монтирование скроет файлы из образа.
6. **Шрифт Inter** подключается с Google Fonts: без интернета страница откатится
   на Segoe UI. Для автономной демонстрации положите `Inter-*.woff2` в `web/fonts/`.
7. **Безопасность `/admin`.** Статический пароль, нет CSRF-защиты и блокировки
   перебора — для прототипа допустимо, для стенда требуется доработка.
8. **`/api/check` без авторизации.** Задача этого не требовала; при выкладке на
   стенд закройте тем же `AIS_TOKEN` или отдельным режимом.
