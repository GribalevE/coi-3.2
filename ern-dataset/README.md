# ern-dataset — сервис основного датасета ЕРН

Отдельный проект: хранит основной датасет (лица, паспорта, родство, записи
ЗАГС, разводы, дееспособность, занятость, налоги, права) и отдаёт его по HTTP.
Сервис проверки `coi-1` забирает датасет при старте и сам его не хранит.

Реестр должностных лиц таможенных органов здесь **не хранится**: он правится
через `/admin` в `coi-1`, поэтому остаётся локальным файлом того сервиса.

Все сведения синтетические и не относятся к реальным лицам.

---

## 1. Структура проекта

```
ern-dataset/
├── go.mod                          модуль ern-dataset, только стандартная библиотека
├── README.md                       этот файл
├── .gitignore
├── cmd/
│   └── ernserver/
│       └── main.go                 точка входа: флаги, сборка сервера, остановка по Ctrl+C
├── internal/
│   ├── dataset/
│   │   └── store.go                чтение файла, SHA-256, разбор счётчиков
│   └── httpapi/
│       └── server.go               маршруты /health, /api/v1/meta, /api/v1/bundle
├── data/
│   └── dataset.json                основной датасет (переносится из coi-1/data)
├── scripts/
│   ├── build.ps1                   go mod tidy + go build в bin\ern-dataset.exe
│   └── run.ps1                     сборка при необходимости и запуск
└── docs/
    └── API.md                      описание эндпоинтов с примерами
```

Разделение по пакетам сделано не для красоты: `dataset` ничего не знает про
HTTP, а `httpapi` — про файловую систему. Проверку данных можно менять
независимо от маршрутов.

## 2. Требования

- Go 1.22 или новее (проверить: `go version`);
- Windows PowerShell 5.1 или PowerShell 7 — для скриптов; без них всё
  запускается командами `go` напрямую;
- свободный порт 8091.

Внешних зависимостей нет — `go.mod` без `require`, `go mod tidy` ничего не
скачивает.

## 3. Быстрый старт

```powershell
cd ern-dataset
# положить файл датасета
copy ..\coi-1\data\dataset.json data\dataset.json

.\scripts\run.ps1
```

Скрипт соберёт `bin\ern-dataset.exe` (если его нет) и запустит сервис.
Проверка в другом терминале:

```powershell
curl http://localhost:8091/health
```

Ожидаемый ответ:

```json
{
  "status": "ok",
  "version": "v1.0.0",
  "file": "dataset.json",
  "size": 139424,
  "sha256": "…",
  "counts": {
    "persons": 230,
    "kinship": 37,
    "civil_registry": 18,
    "divorce": 7,
    "tax_registration": 46
  },
  "checked": "2026-11-20T09:15:00Z"
}
```

## 4. Сборка и запуск по отдельности

```powershell
# сборка
.\scripts\build.ps1

# запуск собранного файла
.\bin\ern-dataset.exe -addr :8091 -dir data -version v1.0.0

# запуск без сборки, из исходников
go run .\cmd\ernserver -addr :8091 -dir data
```

## 5. Параметры

| Флаг | Переменная | По умолчанию | Назначение |
|---|---|---|---|
| `-addr` | `ERN_ADDR` | `:8091` | адрес и порт HTTP-сервера |
| `-dir` | `ERN_DIR` | `data` | каталог, в котором лежит `dataset.json` |
| `-version` | `ERN_VERSION` | `v1.0.0` | версия датасета: в журнал, `/health`, заголовок `X-Dataset-Version` |

Путь к файлу всегда `<dir>/dataset.json`. Если файла нет, сервис не стартует
и пишет причину — молча подниматься с пустым датасетом он не должен.

## 6. Эндпоинты

| Метод и путь | Что отдаёт |
|---|---|
| `GET /health` | состояние сервиса и счётчики датасета; `503`, если файл пропал или не разбирается |
| `GET /api/v1/meta` | файл, размер, время изменения, SHA-256, количество записей |
| `GET /api/v1/bundle` | датасет целиком (`application/json`), `ETag`, `X-Dataset-SHA256` |

Подробности и примеры — в `docs/API.md`.

Файл читается на каждый запрос, кэша нет: замена `dataset.json` действует
сразу, перезапуск сервиса не нужен. `ETag` считается по SHA-256, поэтому
потребитель может не качать датасет повторно (`If-None-Match` → `304`).

## 7. Формат датасета

Тот же контракт, что у `internal/data.Bundle` в `coi-1`:

| Секция | Содержимое |
|---|---|
| `persons` | лица: `id`, `full_name`, `passport`, `address`, `city`, `street`, `house`, `birth_date`, `snils`, `inn`, `citizenships`, `emancipated` |
| `kinship` | связи: `a`, `b`, `kind` (`parent`/`spouse`/`sibling`), `civil_id` |
| `civil_registry` | записи ЗАГС: `id`, `a`, `b`, `kind` |
| `divorce` | расторжение брака: `a`, `b` |
| `guardianship`, `emancipation`, `parental_rights` | опека, эмансипация, родительские права |
| `legal_capacity`, `employment_service`, `tax_registration`, `driver_license` | дееспособность, занятость, ОГРНИП, права |

Сервис проверяет только наличие непустой секции `persons`. Полную схему и
ссылочную целостность проверяет `coi-1` при загрузке (`data.Load` →
`Bundle.Validate`): неизвестные поля отвергаются, ссылки на отсутствующих лиц
считаются ошибкой. Такой порядок выбран намеренно — за форматом следит тот,
кто его потребляет.

## 8. Как обновить данные

1. Заменить `data/dataset.json` новым файлом.
2. Убедиться, что сервис видит новую версию: `curl http://localhost:8091/api/v1/meta`
   — изменится `sha256` и `modified`.
3. Перезапустить `coi-1`, чтобы он забрал датасет.

Датасет можно пересобрать из SQL-дампа средствами `coi-1`:

```powershell
cd ..\coi-1
go run .\cmd\seed -in data\ern_full.sql `
    -persons ..\ern-dataset\data\dataset.json `
    -dltos data\dltos.json
```

## 9. Связка с coi-1

```powershell
# терминал 1
cd ern-dataset; .\scripts\run.ps1

# терминал 2
cd coi-1
$env:COI_DATA_URL = 'http://localhost:8091'
.\scripts\run.ps1
```

`coi-1` забирает `/api/v1/bundle` при старте (три попытки с паузами, таймаут
20 с на запрос) и пишет в журнал источник данных. Если сервис не поднят,
`coi-1` не стартует — подменять данные локальным файлом молча нельзя.

Реестр `data/dltos.json` остаётся в `coi-1`: его меняет `/admin`.

## 10. Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| `датасет: файл датасета: ... cannot find the file` | нет `data\dataset.json`; положить файл или указать `-dir` |
| `в датасете нет записей в секции persons` | файл не тот или повреждён: проверить `sha256` и размер |
| `listen tcp :8091: bind: ...` | порт занят: другой `-addr`, например `:8092`, и такой же `COI_DATA_URL` в `coi-1` |
| `503` на `/health` | файл исчез или перестал разбираться после замены |
| `coi-1` пишет «сервис данных недоступен» | сервис не запущен либо порт/bind не совпадают; проверить `curl /health` |

## 11. Ограничения прототипа

- Сервис только читает файл: загрузки, валидации на запись и версионирования
  датасета нет.
- Авторизации нет — предполагается внутренний контур.
- Один файл целиком в памяти на каждый запрос; для 150 КБ это несущественно,
  для гигабайтных выгрузок понадобился бы потоковый формат.
- Проверка схемы ограничена секцией `persons` (см. §7).
