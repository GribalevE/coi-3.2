# COI LDT — запуск решения

Решение уже собрано. Ничего устанавливать, компилировать и настраивать не нужно:
распакуйте архив и запустите один файл.

## Как запустить

1. Распакуйте архив **целиком** в любую папку без кириллицы в пути,
   например `C:\coi\`. Важно, чтобы все файлы легли рядом, а не по одному.
2. Двойной щелчок по **`START.cmd`**.

Дальше всё автоматически: проверка файлов, запуск двух сервисов, открытие
браузера на `http://localhost:8080`.

Если Windows покажет «Windows защитила ваш компьютер» — «Подробнее» →
«Выполнить всё равно». Это стандартное предупреждение для любого скачанного
`.exe` без платной подписи.

## Что должно лежать в папке

```
C:\coi\
├─ START.cmd               двойной щелчок
├─ coi-launcher.exe        сам лаунчер
├─ coi-1\                  сервис проверки   (bin\coi.exe, data\dltos.json)
└─ ern-dataset\            сервис данных     (bin\ern-dataset.exe, data\dataset.json)
```

Лаунчер сам ищет папки сервисов рядом с собой (и на уровень-два выше), так что
имена папок и место запуска значения не имеют.

## Что делает лаунчер при старте

| Шаг | Действие |
|---|---|
| 1 | находит папки обоих сервисов |
| 2 | проверяет `data\dataset.json` и `data\dltos.json` |
| 3 | проверяет, что собранные `.exe` на месте и не повреждены |
| 4 | снимает блокировку скачанных файлов (SmartScreen) |
| 5 | если порт 8091 или 8080 занят — берёт следующий свободный |
| 6 | предупреждает, если остался старый журнал проверок |
| 7 | запускает сервис данных, ждёт готовности, запускает сервис проверки |
| 8 | открывает браузер |

Остановка — `Ctrl+C` в окне лаунчера (оба сервиса гасятся). Если окно просто
закрыть, сервисы могут остаться в памяти; тогда закройте процессы `coi.exe` и
`ern-dataset.exe` в диспетчере задач.

## Если что-то не так

| Сообщение | Что сделать |
|---|---|
| `не найдена папка сервиса данных/проверки` | распаковать архив целиком, папки `coi-1` и `ern-dataset` должны лежать рядом с `START.cmd` |
| `нет файла данных ...` / `нет реестра ...` | архив распакован не полностью — распаковать заново целиком |
| `повреждён при скачивании` | скачать архив заново (файл `.exe` недокачался) |
| `порт ... занят` | ничего делать не нужно, лаунчер сам возьмёт соседний порт и напишет адрес |
| `журнал проверок уже есть` | для чистой демонстрации: `START.cmd -reset` |
| окно закрылось сразу | запускайте через `START.cmd` — он оставляет окно открытым при ошибке |

## Для проверяющего: параметры и коды выхода

```powershell
.\coi-launcher.exe -check          # только диагностика, без запуска
.\coi-launcher.exe -reset          # чистая демонстрация (удаляет var\coi.db)
.\coi-launcher.exe -no-browser
.\coi-launcher.exe -h              # -root, -dataset-dir, -app-dir, -data-exe, -app-exe, -data-port, -app-port, -token
```

Коды выхода: `0` — отработал и штатно остановлен, `2` — есть неисправимый FAIL,
`3` — сервис не поднялся или упал. `START.cmd` возвращает тот же код и держит
окно открытым при ненулевом.

Проверка на данных из архива: поручение по `DL-014` (ЗАЙЦЕВ АЛЕКСЕЙ ПАВЛОВИЧ,
паспорт `6605 856401`) — ожидаются K-01 и K-02 уровня critical и K-10 warning.

## Сборка (только для разработчика)

Лаунчер собирается тем же Go, что и сервисы, один раз — и в архив попадает
готовый `.exe`:

```powershell
cd launcher
.\build.ps1          # = go build -trimpath -o .\coi-launcher.exe .
```

Внешних зависимостей нет — только стандартная библиотека. Без Go вместо
`coi-launcher.exe` работает `launcher.ps1` с теми же проверками:
`powershell -ExecutionPolicy Bypass -File .\launcher.ps1 -Check`.

## Что проверено, а что нет

- Проверено разбором исходников: баланс скобок, отсутствие неиспользуемых
  импортов, соответствие флагов сервисам (`-addr`, `-dir` — данные; `-addr`,
  `-token`, `COI_DATA_URL` — проверка).
- **Не проверено:** `go build`, `go vet`, реальный запуск, синтаксис
  PowerShell/CMD — в среде подготовки нет ни Go, ни Windows. Первый `go build`
  смотрите глазами: сообщение укажет файл и строку.
